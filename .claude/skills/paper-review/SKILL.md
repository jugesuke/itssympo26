論文の対象部分を、書き手との会話を知らないサブエージェントに読ませる。
このスキルを動かすエージェントは、サブエージェントを呼ぶ役に徹する。

- `paper-reader`：初めて読む読み手として、読み取った内容と問い返したい箇所を返す
- `academic-writing-reviewer`：アカデミックライティングの観点で、引っかかった箇所を返す
- `typesetting-reviewer`：図表・数式・記号・表記の作法の観点で、引っかかった箇所を返す。
  textlint などで機械的に検出できるものと、学会テンプレートが決めているものは扱わない

## 1. 対象を決める

`$ARGUMENTS` にファイルのパスか節の名前があれば、それを対象にする。
無いときは、エディタで開かれているファイルを対象にする。
それでも決まらないときは、どこを読ませるかを書き手に聞く。

## 2. 入口と読み手を決める

- 入口：`main.tex` など、論文をビルドするファイル
- 読み手：タイトルやスタイルファイルから投稿先が分かれば、その場に来る研究者とする

## 3. サブエージェントを呼ぶ

3 つのサブエージェントを、1 つのメッセージの中で並列に呼ぶ。
どれにも同じプロンプトを渡す。

**毎回、新しいサブエージェントを呼ぶ。**
前の回のサブエージェントに SendMessage で続きを頼まない。
前の版を読んだサブエージェントは、直した版を初めて読む人として読めない。

プロンプトに入れるのは、次の 3 つだけ。

```
論文の入口：main.tex
対象：documents/03_研究課題.tex（3 章「研究課題」）
読み手：第 N 回 ITS シンポジウムの参加者
```

書き手が「まだ入れていない」と言ったもの（引用、図表など）があるときだけ、その種類を 1 行足す。
中身の説明は足さない。

```
見ない観点：引用はまだ入れていないので、引用が無いことは挙げない
```

入れないもの：

- 書き手の意図、この節で言いたいこと
- 用語の説明、背景の補足
- 前の回のレビュー結果、前の回から直したところ
- 書き手との会話の中身

これらを入れると、サブエージェントは論文に書かれていないことを知った状態で読む。
論文に足りないことが、返ってくる内容に出てこなくなる。

文章はパスで渡す。本文を貼り付けない。
サブエージェントは前の章から順に読むので、ファイルをたどれる必要がある。
書き手がまだファイルにしていない文章を渡してきたときだけ、その文章をプロンプトに入れる。

## 4. 書き手に返す

3 つの結果をまとめて、次の 2 つを書き手に見せる。

1. **読み取った内容**：`paper-reader` が返したものをそのまま見せる
2. **指摘**：`paper-reader` の問い返しと、`academic-writing-reviewer` と `typesetting-reviewer` の指摘を 1 つの一覧にする
   - 原文に出てくる順に並べる。画像への指摘は、その図を取り込む箇所に並べる
   - 1 件ごとに原文を引き、問い返しか、どのサブエージェントのどの観点かを書く
   - 同じ箇所への指摘は 1 件にまとめ、それぞれの中身を残す

サブエージェントの答えは正しいものとして扱う。
まとめるときにソースを開いて確かめ直さず、指摘の中身も変えない。

- サブエージェントの問いに、代わりに答えない
- 直し方を足さない。書き手に頼まれたときだけ一緒に考える

書き手が直したら、もう一度このスキルを呼んでもらう。
