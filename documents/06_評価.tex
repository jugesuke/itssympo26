\subsection{headsignの構造化の評価}

本稿で示した手法により，headsignの構造化を実施した．
AIエージェントとして，Claude Code Opus 5.5（effort: high）を使用した．
函館バス 五稜郭バス停・青森市営バス 青森駅バス停を発車する便に対して，headsignの構造化を行わせた．
処理中の動作をロギングし，比較を行った．
結果は\cref{tab:headsign-result}のようになった．

まず，最初の抽出では半数前後が検査に落ちるものの，繰り返し作業し修正を重ねれば問題なく検査を通過することが分かった．
函館バスの処理において検査でエラーとなった表示は\cref{tab:headsign-error-goryokaku}に示す通り．
半分以上が\~前の省略か略称であった．
これらの多くは停車列から復元できる．
また，費用と時間については，現実的な範囲に収まったといえる．

一方で，検査で確かめているのは「実在する停留所名か」だけであり，意味が正しいかは確かめていない．
今回の評価では致命的な誤りは確認できなかったが，意味的な正当性を評価する仕組みが必要になる可能性は依然としてある．
特に地域名を指すような用語についての知識を外部から与える手段が必要である．

\subsection{方面別分類の評価}

本稿で示した手法により，方面別分類を実施した．
AIエージェントとして，Claude Code Opus 5.5（effort: high）を使用した．
八戸市営バス 八戸中心街ターミナル（三日町・八日町・中央通り・六日町・朔日町）バス停・函館バス 亀田支所前バス停を発車する便に対して，方面別分類を行わせた．
処理中の動作をロギングし，比較を行った．
また，事業者がどう分類しているかをもとに，結果の妥当性を比較した．
八戸市営バスでは，事業者が用いている路線記号を基準とした．
函館バスでは，亀田支所前バスターミナル内ののりばが方面別になっていることを利用して，のりばを基準とした．
結果は\cref{tab:direction-result}のようになった．
事業者の分類との比較は\cref{tab:direction-hachinohe}・\cref{tab:direction-kamedashisho}のようになった．

人間による分類では時間がかかる方面別分類の作業が，小さなコスト・短い時間で実現できた．
方面別分類の結果については，事業者の分類におおむね従い，一部分割・併合させた分類が採用された．
また，亀田支所前での分類では，利用実態からほぼ同一といえる3番のりばと5番のりばが同一と判断された．
これらのりばは，路上かターミナル内かの差しかなく，同じ方面のバスが停車している．
その点でも正当な分類となったといえる．

一方今回の分析では，事業者の分類と対照づけて比較できる2か所のみでしか実施していない．
GTFSの記載内容は事業者によって大きく異なることから，より多くの事業者のデータで実験を実施すべきである．
しかし，事業者の示す分類と合致することは必ずしも目指すところではない．
方面分類の基準があいまいである以上，切り分け方にはバリエーションがあり，場合によって使い分けられるべきである．
本研究で目指す，小規模なバス停に対しての方面分類については，事業者が分類を行うことは少ないため，そもそも比較が困難である．
また，事業者の示す分類が必ずしも旅客の認識と合致するとも限らない．
利用者認識と合致しているかを確かめるため，分類結果を実際の利用者に評価させる必要性がある．
この点は，今後の課題とする．
